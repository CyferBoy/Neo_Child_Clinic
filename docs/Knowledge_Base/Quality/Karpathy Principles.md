# Karpathy Principles: First-Principles Code Review & Engineering

> *“Build from scratch. Understand every layer of the stack. Zero unnecessary abstractions. Strip away magic.”*

## Core Rules

1. **First-Principles Derivation**: Never accept an abstraction or pattern merely because "that's how it's done" or because a framework suggests it. Derive the correctness of data flow, transactions, and state management from the raw mechanics of the platform, database, and hardware.
2. **Zero Magic / No Hidden State**: Avoid implicit behaviors, opaque lifecycle magic, or overly clever macro-frameworks where a simple, transparent data flow or explicit transaction block suffices.
3. **Inspect the Raw Tokens/Bytes/SQL**: Understand the exact SQL queries generated by ORMs (like Room), the exact HTTP payloads sent to backends (like Supabase PostgREST), and the exact coroutine contexts and dispatchers executing state updates.
4. **End-to-End Mental Simulation**: Before touching code, trace the data flow end-to-end (UI → ViewModel → Domain/Use Case → Repository → Database/Network → Back to UI) under adversarial conditions (partial failures, concurrency races, offline reconnections).
5. **Radical Simplicity**: If a feature or abstraction can be achieved in 10 lines of explicit code instead of 3 layers of indirection and interfaces, delete the layers.
